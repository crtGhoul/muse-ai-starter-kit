🔌 Muse.ai Connections — explained, with the add line

First, the distinction that matters: consumer Muse (muse.ai, phone, Mac, WhatsApp) is not the same as the Meta Model API (for developers building their own agent) or Muse Code CLI (a terminal coding agent). Most add-lines below are for consumer Muse. Where there is no official add-flow, this page says so plainly instead of borrowing another product's flow.

Beginner ladder: built-in connector → custom connector → Zapier → browser fallback → developer route (Model API / Muse Code / platform submission).

Built-in connectors

Official

What it is: A curated list of apps Meta built with the provider, shown in Muse under Settings → Connectors.

What it does: Let Muse read or act in an app you already use, after you sign in to that app, with approval before sending, publishing, or spending.

Settings → Connectors → Connect → Continue → sign in  —  or in chat: Connect my Gmail

Custom connectors

Official, unreviewed by Meta

What it is: Muse itself writes a small integration on its cloud VM for a service not in the directory, if that service has a public API or CLI.

What it does: Makes an unlisted service usable in chat and saves it as a reusable skill for later conversations.

Build a custom connector for [service] using its API docs at <URL> / MCP server at https://<host>/mcp. Test it and save it as a skill.  —  put any key only in Muse's separate secure credential prompt, never in chat.

MCP — consumer Muse

No official settings flow

What it is: The open Model Context Protocol: an AI client discovers and calls tools on an MCP server instead of bespoke code per app.

What it does: Lets Muse call tools on a hosted MCP server, indirectly, via a custom connector or a directory MCP connector. A server running only on your laptop is unreachable from Meta's cloud VM.

No official add-flow found — do not paste an MCP JSON config into a consumer Muse settings file. Use the custom-connector chat prompt above, or a directory MCP connector like Zapier.

MCP — Muse Code

Official (developer only)

What it is: The same MCP protocol, but for Meta's terminal coding agent, not the consumer app.

What it does: Gives the coding agent extra tools (docs search, email, and more). Key name is disputed across sources — verify before copying.

~/.config/muse/settings.json — verify key name first: {"schema_version": 1, "mcp_servers": {"wearables": {"transport": "streamable_http", "url": "https://mcp.developer.meta.com/wearables"}}}  —  then restart Muse Code / start a new session.

Meta Model API

Official (developer only)

What it is: Meta's developer API for Muse Spark/Wonder models, for building your own agent or app.

What it does: Builds your own chatbot/agent powered by the same model family. It does NOT remote-control your Muse app or add a connector to it.

dev.meta.ai → API keys → Create API key → copy it immediately (shown once) → set it as an env var, never hard-code it. Verify base URL and endpoints in dev.meta.ai docs before hard-coding.

Webhooks — Muse.ai

No official flow

What it is: An inbound event endpoint that would let an outside system push events into Muse.

What it does: None found. There is no Muse webhook URL to paste anywhere. Do not invent one.

No official add-flow found. Closest beginner flow is via Zapier (below).

Webhooks via Zapier

Official vendor connector

What it is: Zapier's Webhooks by Zapier trigger: an outside system posts to a Zapier URL, a Zap runs, Muse can act through the Zapier connector.

What it does: External event → Zap → Muse action, or Muse asks Zapier to build a Zap. The webhook belongs to Zapier, not to Muse.

Muse → Settings → Connectors → Zapier → Connect → sign in → Allow — then in Zapier, the Catch Hook URL goes into the source system, not Muse.

Zapier connector

Official, staged rollout

What it is: A named directory connector that is itself a hosted MCP endpoint.

What it does: Opens 9,000+ apps and 40,000 actions through one connector, approval-gated. Free to connect; each action consumes Zapier tasks from your plan.

Settings → Connectors → Zapier → Connect → sign in → Allow

Custom agents / assistants

No official flow

What it is: A separate, shareable custom-assistant builder, GPT-style.

What it does: None found for the consumer app. What exists is personalisation inside one Muse: name, avatar, tone, memory, remember/forget.

No official add-flow found for a custom-assistant file or builder.

Skills / custom instructions

No official file flow

What it is: A saved skill or instruction file you upload to Muse.

What it does: None as a file upload. Muse saves a custom connector as a reusable skill internally, and you can set preferences in chat.

No official add-flow found for a skill file. In chat: Remember… / Forget… — SKILL.md is a generic pattern, not Muse.ai's documented format.

Artifacts / share links

Official

What it is: Documents, static Pages, and interactive apps Muse builds in its Library.

What it does: Keep a file, host a live static page, or publish a static page via a link. Interactive apps cannot be published publicly; each publish and each update needs fresh approval.

Artifact menu → Share → approve (re-approve every update). Delete in Library to revoke the link permanently.

Muse Code CLI

Official (developer only)

What it is: Meta's terminal coding agent (muse command) for macOS/Linux/Windows.

What it does: Plans, writes, and validates code across repos with sub-agents and approvals. Separate from the consumer app; its subscription does not raise consumer allowance.

curl -fsSL https://dev.meta.ai/install.sh | bash  —  then: muse --version  —  then: cd <project> && muse

Mobile / desktop / WhatsApp

Official

What it is: iOS, Android, Mac, web at muse.ai, and WhatsApp surfaces for the same agent.

What it does: Same agent/thread everywhere. Mac app has per-app access to Files, Messages, Calendar, Notes, Mail. No Windows/Linux desktop agent app found.

Download the Muse app, open muse.ai, or message Muse in WhatsApp. Grant Mac per-app access only for apps you intend.

Browser fallback

Official fallback, not a connector

What it is: Muse drives a website in its Secure VM when there is no API.

What it does: Fill forms, compare prices, research, or check out where the site allows it. Fragile, and some sites block agents.

Ask Muse to do the task on the site, and watch first runs. No connector to add.

Honest notes

Not affiliated with Muse.ai or Meta. Connector availability is rollout- and account-dependent — check Settings → Connectors in your own Muse app on the day. Announced partners flagged above were not confirmed live in October app checks. Model API base URLs, endpoint paths, and model IDs are widely reported but were not printed on the official Model API page excerpt fetched for the research behind this page — verify them in dev.meta.ai docs before hard-coding. Bonus terms for code 0NS5DG are whatever Muse.ai shows on its own signup screen; this page does not guarantee a token amount. This catalogue is about Muse.ai consumer connections only.

Sources used for this page: Meta Model API product page (developer.meta.com), Zapier's Muse connector posts, Meta Wearables MCP docs, and secondary pages quoting Meta Help Center, including Parallel's Muse custom-integrations article. Full research notes are in the project's research folder, not published here.
